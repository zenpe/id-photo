# 分批实施与 Review 记录

> Historical Vue 2 record. Current migration results and acceptance scope: [Vue 3 migration](migration-vue3.md).

本地代码验证与 NAS、微信平台、EdgeOne/Lucky 的实机验收分别记录。

## 第 0 批：当前修复基线

- 方案：收拢 Node 24 安装/构建、上传诊断、默认标准版，并保持已有 MTCNN 精确异常处理。
- Review：服务状态原先仍检查两个旧默认模型，已统一检查 Hivision MODNet；可选模型仍单独检查。
- Review：用户本地 AppID 修改与 `.env.local` 不纳入本批提交；上传日志不输出图片和 Authorization。
- 已验证：Node 24 严格依赖安装、微信与 H5 构建、保存/相机/加载流程，以及 7 项人脸异常回归（此前执行）。
- 实机待验收：NAS 更新后的实际照片、人脸失败提示、8090 回源、Invalid HTTP request 来源及镜像回退。
- 后续批次不自动改变 NAS 现有配置，不宣称尚未连接的设备已完成部署。

## 第 1 批：保存与广告解耦

- 方案：默认免费；策略管理器与微信广告适配器分开；五类保存入口统一授权。
- Review：只有明确观看完成才授权，取消不进入免费兜底；会员查询失败不强迫观看。任务授权有 30 分钟有效期、50 条上限，仅保存在内存中。
- Review：移除页面保存成功后清空广告授权的行为；相册保存失败后可重试。免费模式不依赖会员接口。
- 已验证：12 项广告/会员场景及加载、电子照预览、六类相机入口回归通过。
- 待实机：微信广告资格与真实 SDK、相册权限及 H5 浏览器下载兼容性。

## 第 2 批：自有配置与能力开关

- 方案：后端提供不含凭据的 `/capabilities`；前端每分钟刷新，失败退回免费保存并关闭购买和异步入口。广告位只由后端显式启用。
- Review：购买按钮之外还保留后端支付开关；异步检测接口新增开关拒绝。订单和现有会员查询继续保留。配置响应禁止缓存。
- Review：删除上游默认域名、广告位、客服邮箱和二维码入口；品牌、主体和联系信息统一配置。生产构建检查缺项，保留本机 AppID 与环境文件。
- 已验证：微信构建通过；既有流程、人脸及服务状态回归通过；公开策略默认值、无凭据泄露、无效配置拒绝通过。
- 待上线：填写自有主体及联系方式，对照实际审计留存策略确认协议；CDN 对全部 API 禁用缓存；发布构建检查不替代微信平台资格审核。

## 第 3 批：制作失败恢复

- 方案：每类工具一份本地草稿，保存文件副本和少量参数，一天有效；继续制作、丢弃及统一清理。草稿写入失败不阻断当前处理。
- Review：草稿元数据在所有文件复制成功后才替换；写入失败保留旧草稿。普通临时文件清理不删除草稿副本；启动时清理过期及崩溃遗留文件。
- Review：转换参数变更不清空旧结果，旧预览有说明；证件照相同参数保存复用结果，失败后仍保留上一份成功结果。权限拒绝可跳转设置；超时不自动重发长任务。
- 已验证：草稿持久化、写入失败回滚、缺失文件、过期与范围清理；旧结果保护与相册失败重试；原流程回归及微信构建通过。
- 限制：草稿恢复仅实现微信本机，不做跨设备同步；系统强制终止且尚未写入的修改不能保证恢复。电子照仍使用现有最多两张的本地记录，保存满额会提示，不静默覆盖。

## 第 4 批：可选完整部署

- 方案：同一镜像的 API、push、admin profiles，默认 API 映射 8090；配置与数据路径从本地环境传入，各角色使用独立环境文件。
- Review：原后台仅接受回环客户端，直接桥接端口会 403；采用 Linux host 网络并保持进程监听回环，通过 SSH 隧道访问，未放宽后台的 Host/Origin/认证限制。
- Review：补齐后台资源和服务各自健康端点；发现首次并发迁移竞态，迁移检查与 ALTER 在同一写事务中串行，六线程全新数据库启动通过，身份密钥一致、套餐不重复。
- Review：Gradio 演示初始化移到显式运行入口，API 不再下载演示依赖。固定数值栈，镜像内记录 pip freeze；完整传递依赖锁仍需根据成功构建的解析清单冻结，未伪称已验证。
- 已验证：Compose 2.40 的三个 profiles 配置解析、Python 语法、人脸/公开能力/并发启动回归通过。
- 已提供但尚未执行：镜像内 API/push/admin 边界与静态资源回归、真实模型冒烟 CI、NAS 一致性备份及全新目录恢复检查。
- 外部限制：本机 Docker daemon 未运行、未连接 NAS，不能构建/启动镜像，也未执行真实回调、照片和恢复演练。上线前必须完成这些验收。

## 第 5 批：仓库收口与整体 Review

- 方案：归档手动电子照调试文件与 macOS 恢复脚本；前端仅保留微信/H5 命令，统一 README、联调和 fnOS 部署入口，历史运营记录明确标为上游历史。
- Review：后台仍残留上游公网探测地址与固定本地 8080，已改为显式配置；未开启的 push 不再使后台监控误报降级。后台局域网/公网安全边界保持原样。
- Review：移除未使用的 uni-automator/Jest 依赖并重生成锁文件，保留 Node 24 的 IPC 兼容锁定；旧增强编辑路由不再注册，文件仍保留供后续迁移参考。
- Review：修正源照片页退出可能覆盖编辑草稿、广告错误回调等待过长、关闭购买时仍展示套餐准备中等边界；电子照保存前也显示当前保存规则。
- Review：发布构建拒绝上游 AppID、占位地址和缺失自有信息；CI 显式使用假 AppID 配置。本机用户 AppID 及 `.env.local` 仍未纳入提交。
- Review：电子照工具底层还会静默删除最旧照片，且读取失败会当作空库；已改为满额或读写失败即拒绝新增，保留原记录，并移除未调用且会破坏 Base64 的伪压缩函数。隐私说明补充真实审计范围、大小轮换及统计期限。
- Review：API 中间件统一返回 `Cache-Control: no-store`，包括鉴权失败响应；CDN 仍须按部署文档显式绕过缓存。
- 已验证：精简后严格离线锁文件安装、九组 Node 回归、TypeScript 检查、13 项 Python 回归及语法检查通过；微信/H5 最终构建均通过。
- 本批不把 CI 定义当作 CI 已成功运行，不把本地构建当作 NAS 上线。

## 发布前剩余验收

1. 新 CI 或 NAS 完成 amd64 镜像构建、三角色启动、真实默认模型冒烟；根据成功解析结果制作完整 Python 锁并保存已验证镜像。
2. NAS 更新至相同提交，完成单人/无人脸/多人脸、公网与直连对照，定位持续 HTTP 解析警告和 524。
3. 微信真机验证登录、内容安全、保存权限、退出恢复及广告 SDK；拥有广告资格后才启用对应策略。
4. 按实际主体填写品牌、联系方式和隐私内容，核对审核元数据的真实留存周期；校验 CDN 全 API 不缓存。
5. 在 NAS 执行停止备份与全新目录恢复演练；开启 push 后完成微信回调真实验签；支付上线另做完整验收。
